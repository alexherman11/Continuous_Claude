**THE HIERARCHICAL ROUTING PROBLEM**

Most routing systems ask: "Given this request, which model?"

But real-world model selection happens at multiple timescales:

**Level 1: Strategic (session/user level)**
- "This user is a developer building a complex app" → allocate capable model
- "This is a casual chatbot interaction" → allocate fast/cheap model
- Decision features: user profile, task category, cost budget, expected session complexity
- Timescale: per-session or per-user

**Level 2: Tactical (turn level)**
- "This specific message needs code generation" → maybe escalate
- "This is a simple follow-up acknowledgment" → maybe downgrade
- Decision features: message content, conversation state, task decomposition
- Timescale: per-turn

**Level 3: Operational (subtask level)**
- "This request needs both creative writing AND fact-checking"
- Route the creative part to one model, verification to another
- Decision features: subtask decomposition, pipeline structure
- Timescale: within a single request

**The key insight: these levels interact.**

A strategic decision to allocate Opus means the tactical router rarely needs to escalate. A strategic decision to allocate Haiku means the tactical router is constantly escalating, which is *more expensive* than just starting with a better model.

This suggests there's an **optimal allocation frontier** - a curve relating:
- Strategic model allocation (capability level)
- Tactical escalation frequency
- Total cost
- Quality achieved

If you start too cheap, escalation costs eat your savings. If you start too expensive, you're overpaying for simple turns. The optimal point depends on the *variance* of task complexity within a session.

**This is actually formalizable.**

Let me think about it mathematically:

Let C(m) = cost per token for model m
Let Q(m, t) = quality of model m on task t
Let p(t | session_type) = distribution of task complexity within a session

For a single-level router (per-message):
- Total cost = Σ C(m*(t_i)) for each message i
- Where m*(t_i) = argmax Q(m, t_i) subject to some cost constraint

For a two-level router:
- Strategic: choose base model m_base for the session
- Tactical: escalate to m_high when Q(m_base, t_i) < threshold
- Total cost = Σ [C(m_base) * (1-e_i) + C(m_high) * e_i] 
- Where e_i = 1 if escalation triggered

The interesting question: **when does two-level routing beat single-level?**

Hypothesis: When task complexity variance within sessions is LOW (most messages are similar difficulty), strategic allocation wins. When variance is HIGH (wildly different difficulty per message), per-message routing wins.

This predicts:
- Coding sessions → strategic allocation (consistently complex) 
- General assistant → per-message routing (unpredictable complexity)
- Customer service → strategic allocation (predictable patterns)

**My own case validates this.** Alex's work with me has consistently high complexity - research, tool use, building things. Strategic allocation to Opus makes sense because the variance is low (I'm almost always doing complex work). Per-message routing would waste overhead on escalation decisions.
